## "Полка раздора"

Условие: От квадратной доски по горизонтали отпилили прямоугольник шириной a, а потом по
вертикали прямоугольник шириной b, остался прямоугольник площадью S. Определить целочисленную сторону исходной исходной доски. Изначальная доска имеет форму квадрата.

Решение:
Площадь получившегося прямоугольника после разрезов можно определить так:
`S = (M-a)*(M-b)`

Решение по-идее состоит в том, чтобы просто подобрать значение площади от 0 до верхнего
ограничения. То есть мы, используя бинарный поиск просто ищем оптимум M, принимающий значения
от 0 до N, такие, что (M-a*M-b >= S). Нам нужен первое такое хорошее значение, поэтому используем формулу левого бинарного поиска:

```py
def good(m, checkparams):
    a, b, S = checkparams
    return m >= a and m >= b and (m-a)*(m-b)>=S

def lbinsearch(l, r, check, checkparams):
    while l < r:
        m = (l+r)//2
        if check(m, checkparams):
            r = m
        else:
            l = m+1
    return l


a, b, S = map(int, input().split())
l = 0
r = 10**5

L = lbinsearch(l, r, good, (a, b, S))
if (L-a)*(L-b) == S:
    print(L)
else:
    print(-1)
```

В моём же решении всё точно также, за исключением определений левой и правой границ:
```py
# l-a >= 1 && l-b >= 1 => l = max(a,b)+1 (пессимистичный сценарий, всё будет обрезано до 1)
l = max(a, b) + 1
# оптимистичный сценарий: что-то одно может быть обрезано до 1 (L-a)*(L-b)=S, либо L-a=1, либо L-b=1
r = max(a, b) + S
```
Левая граница определилась так, как если бы a и b были бы обрезаны так, чтобы остался `1`,
а правая граница определилась так, что что-то одно может быть обрезано до одного - заведомо правильное значение r - то есть границы здесь определились уже.

## "Обмен валюты"

Условие: Есть массив `C` с натуральнми числами и вещественное число P. Найти C_i/C_j ближайшее к P.

Решение:
1) в идеале нам бы хотелось, чтобы `C_i/C_j = P`
2) тогда давайте пройдёмся по всем `C_i`, зафиксируем каждое и найдём такое `С_j`:
3) `C_j = C_i/P`. И скажем, что это будет идеальным случаем, поэтому пометим такое число, как `C_j'` - идеальное.
4) Тогда нам нужно будет найти `C_j` такие, что они будут больше или равны `C_j'`
5) либо посмотреть ещё влево, на `C_j-1 < C_j'`, потому что разница между ними может быть меньше, чем у `C_j`.
6) Поэтому давайте после того, как найдём это число посмотрим влево, посмотрим вправо и найдём самое подходящее число в знаменателе.

```py
from bisect import bisect_left

# кол-во чисел и число `P`
n,p = map(int, input().split())
# числа массива `C`
nums = list(map(int, input().split()))
sorted_pairs = []
for i in range(n):
    # делаем нумерацию с 1-цы
    sorted_pairs.append((nums[i], i+1))
# сортим
sorted_pairs.sort()
# лучшее отличие, сначала делаем его очень большим
best_diff = 2 * 10**18
# иду по цэшкам
for i in range(n):
    # беру очередное c_i, фиксирую его
    c_1, index_1 = sorted_pairs[i]
    # это то, к чему бы я хотел приблизиться - к идеалу )
    target_c_2 = c_1 / p
    # нахожу бинарным поиском возможную позицию - самую первую среди подходящих
    possible_pos = bisect_left(sorted_pairs, (target_c_2, 0))
    # поиск тех самых окрестностей влево и вправо. Сделал max, min, чтобы не выйти за пределы массива: учитывает неприятную ситуацию, когда нет числа слева,
    # потому что мы попали в самое маленькое число или
    # когда нет числа справа, потому что мы попали в самое большое число в этом массиве цэшек.
    for j in range(max(0, possible_pos-2), min(n, possible_pos+3)):
        if i != j:
            # считываю значение знаменателя и его индекс
            c_2, index_2 = sorted_pairs[j]
            # нахожу значение дроби
            ratio = c_1 / c_2
            # смотрю разницу
            ratio_diff = abs(ratio - p)
            # запоминаю, если эта разница самая подходящая
            if ratio_diff < best_diff:
                best_diff = ratio_diff 
                best_1 = index_1
                best_2 = index_2

print(best_1, best_2)
```

## "Феодальная реформа"

Условие: В каждой вершине дерева записан баланс - целое число (может быть отрицательное). Мв можем прибавлять и вычитать 1 ко всем вершинам на пути от корня до любой вершины.
Превратить баланс всех вершин в 0 за наименьшее количество операций.

Так сложилось, что нужно переводить из феодального бюджета в места (города, сёлы, поселения).
Каждое место обладает каким-то балансом. Наша цель убрать все дисбалансы федерального бюджета - то есть сделать так, чтобы баланс во всех вершинах стал равен нулю.
Что мы можем делать ? Мы можем пойти по какому-то пути и на всём этом пути сделать или +1 или -1 к балансу, но это сложность `O(N^2)` - не подойдёт.

Воспользуемся динамикой по поддереву, похожей на то, что мы уже делали: логика та же, мы у детей что-нибудь спросим, а они нам что-нибудь ответят XD.
Что нужно спрашивать ?
1) во-первых, мы у него спросим, сколько тебе нужно издать реформ, чтобы баланс во всём твоём поддереве стал равен нулю ? Например, в левом доч.узле у нас +1, в правом -1 а в узле 0. Несмотря на то, что в поддереве ребёнка всего три вершины (включая его) нужно издать всего 2 реформы, чтобы всё стало хорошо (один обнулуяет того, где +1, а второй обнуляет того, где -1).
2) во-вторых, нужно спросить у самого ребёнка: как изменится мой баланс (родителя) после того, как я обнулю всё в тебе ? В данном случае, никак не изменится. Потому что мы сначала сделали -1, а потом +1 = в сумме 0 и уйдёт ко мне (родителю тоже 0) 

То есть спрашиваем всего две вещи: сколько реформ тебе нужно издать и как изменится от этого мой баланс ?

Алгоритм:
1) сначала смотрю сколько реформ нужно издать каждому ребёнку, чтобы им стало хорошо. Запоминаю общее количество реформ, которые нужно мне будет издать.
2) затем смотрю как изменится мой баланс после того, как я издам реформы: допустим у меня был баланс -1 и после того, как я изменил одного из ребёнков, у меня стал баланс -4
3) Наверх я отправляю -4. И получается, что общее количество издаваемых реформ будет `2/*для левого*/+3/*для правого*/+4/*для себя после изменений*/=9`.

Решение:
```py
import sys
sys.setrecursionlimit(10**5)

def dfs(now):
    # для рассматриваемой вершины, как будто эта вершина была бы столицей я считаю:
    # 1) количество реформ
    # 2) какой баланс останется в этой вершине (родителе) пробросится выше, в родителя  
    total_edicts = 0
    total_balance = 0
    # перебираю каждого ребёнка
    for child in childs[now]:
        # спрашиваю сколько реформ им нужно и какой баланс они мне вернут
        child_edicts, child_balace = dfs(child)
        total_editcs += child_edicts
        total_balance += child_balance
    # прибавляю к общему количеству реформ разницу баланса в себе и суммарного баланса в детях
    # (например, у меня было `-4`, но в детей пробросилось +4 и мой баланс обнулился за счёт детей) 
    total_edicts += abs(balance[now]-total_balance)
    # прибавляю к сумме баланса разницу баланса в вершине и баланса в детях. 
    total_balance += balance[now] - total_balance
    # возвращаю общее количество реформ и общий баланс, который нужен, чтобы сделать вершины хорошими.
    return total_edicts, total_balance

# число узлов дерева
n = int(input())
# для каждой вершины говорится её предок, но я всё равно строю массивчик детей
childs = [[] for i in range(n)]
for i in range(1, n):
    parent = int(input())
    childs[parent].append(i)
# создаю глобальный массив балансов и запускаю dfs, который принимает 1 параметр - это значение корня
balance = list(map(int, input().split()))
edicts, balance = dfs(0)
print(edicts)
```

## Предок

Необходимо определить, является ли одна вершина предком другой в дереве.
Нам нужно будет два счётчика `T_in`, `T_out`. При входе в вершину счётчик `T_in` увеличивается на 1,
а ппри выходе из вершины (обойдя всех детей, если они есть), счётчик `T_out` обновляется на +1.

Так вот, значения этих меток времени обладают замечательным свойством:
1) если вершина i является предком вершины j, то у нас `T_in_i < T_in_j < T_out_j < T_out_i`.

Это можно представить отрезками времени:
```
T_in_i         T_out_i
[                    ]
    [            ]
    T_in_j T_out_j
```

Почему это работает ? потому что мы очевидно сначала войдём в предка, а потом войдём в потомка.
Поэтому `T_in_i` меньше `T_in_j`, потому что в потомка мы попадаем только из предка.
Почему `T_out_i` больше `T_out_j` ? потому что мы выходим из предка всегда после того, как обошли всех потомков.


```py
import sys
sys.setrecursionlimit(10**5)

def dfs(now):
    global global_time
    t_in[now] = gloabal_time
    gloabal_time += 1
    for child in childs[now]:
        dfs(child)
    gloabal_time += 1 # можно не брать вообще
    t_out[now] = gloabal_time

n = int(input())
parents = list(map(int, input().split()))
childs = [[] for i in range(n+1)]
# cчитываем деревце
for i in range(n):
    childs[parents[i]].append(i+1)
    if parents[i] == 0:
        root = i + 1

# создаём массивы `t_in`, `t_out`
t_in  = [0] * (n + 1)
t_out = [0] * (n + 1)
global_time = 0
dfs(root)

# затем считываем запросы
ans = []
q = int(input())
for i in range(q):
    ancestor, descendant = map(int, input().split())
    if t_in[ancestor] < t_in[descendant] and t_out[ancestor] > t_out[descendant]:
        ans.append('1')
    else:
        ans.append('0')

print('\n'.join(ans))
```
