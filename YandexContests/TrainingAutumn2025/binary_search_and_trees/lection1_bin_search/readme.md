## Что такое бинарный поиск

Загадано число X от 1 до 100. Мы называем Y, нам отвечают, верно ли, что X >= Y.

- (В) Как нам оптимально выигрывать в этой игре ?
- (О) Нам нужно сокращать область где мы будем искать с каждым ответом на вопрос вдвое ! Либо левую половину, либо вторую
- (В) Сколько всего вопрсоов нам нужно задать ?
- (О) Логарифм по основанию два, потому что мы на каждом шаге отбрасываем половинку. 1->2->4->8>16->32->64->128.

## Для каких задач бин. поиск может быть применён ? Алгоритм.

Бывают такие задачи, где сначала "всё плохо", но с какого-то момента становится "всё хорошо" и "всё хорошо" и остаётся.
```
        |
        v
        --------
       |
--------
```
**Допустим**, есть такие задачи: дана последовательность чисел и необходимо найти самое маленькое число Y такое, что
оно больше значения X. X - это число, с которого начинается "всё хорошо". То есть в этой задаче необходимо найти самое маленькое из хороших чисел
и сделать мы это можем с помощью бинарного поиска.

Бывают задачи наоборот, где сначала "всё хорошо", а потом становится "всё плохо".
В этом случае, **могут попросить** найти самое большое из всех хороших чисел. После "хороших" чисел начинаются "плохие"
```
     |
     v
------
      |
      -------
```

Алгоритм (для первого класса задач):
1) каждый раз расчитываем медианный индекс между L и R и спрашиваем, удовлетворяет ли число по этому индексу (Y) неравенству Y >= X,
2) если да, то мы R заменяем на M.
3) если нет, то это число плохое, тогда мы заменяем L на M+1.
4) Повторяем, пока границы не сойдутся.


Пример реализации бинарного поиска, когда сначала всё плохо, но потом становится хорошо. Для поиска первого хорошего числа:
```py
# здесь левая и правая граница анализируются включительно !
def lbinsearch(l, r, check, checkparams):
	while l < r:
		m = (l+r) // 2
		# спрашиваем про среднее число между l и r
		if check(m, checkparams):
			r = m # позже `m` только хорошие числа, которые нам не надо рассматривать, поэтому двигаем
		else:
			# здесь заведомо плохо, делаем +1
			l = m+1
	return l
```

**Всегда нужно проверять свой bin-поиск на двух числах.** Пусть есть всего два числа l и r.
Они отличаются всего на 1. То есть показывают на соседние числа.
Далее, мы смотрим, куда показывает m. В нашем случае, l+r/2 ((10+11)//2=10).
Далее, нужно пройтись по if и else и посмотреть, куда будут показывать l и r.
Идём по if: `10, 11`; `l = 10, r = 11`; `m = 10` => `if true: r = m`. То есть теперь `r` показывает туда же, куда и `l`. На следующей итерации мы выйдем из цикла.
Идём по else: `10, 11`; `l = 10, r = 11`; `m = 10` => `if false: l = m + 1`. То есть `l` показывает туда же, куда и `r`. На следующей итерации мы выйдем из цикла.
Бинарный поиск сошёлся.

А вот если бы **не написали** +1 в ветке `else`, то мы бы никогда не вышли из цикла.

Пример реализации бинарного поиска, когда сначала "всё хорошо", а потом становится "всё плохо". Для поиска последнего хорошего числа.

```py
def rbinsearch(l, r, check, checkparams):
      while l < r:
		m = (l+r+1) // 2
		# спрашиваем про среднее число между l и r
		if check(m, checkparams):
			l = m # раньше `m` хорошие числа, которые нам не надо рассматривать, поэтому двигаем
		else:
			# здесь заведомо плохо, делаем -1
			r = m-1
      return l
```

**Проверка**. Пусть есть два числа `l` и `r`: 10 и 11. m = 10+11+1//2 = 11.
Идём по ветке if: l = 11, тогда `l` указывает туда же, куда и `r`.
Идём по ветке else: r = 11-1 = 10, тогда `r` указывает туда же, куда и `l`.

А вот если бы **не написали** +1 при расчёте m, то тогда бы у нас в ветке if l не сдвинулось.

Вывод: в хорошем bin-поиске у нас всего две ветки `if` и `else`. Нет ветки, которая проверяет на нужное число.

## Задачи на бинарный поиск

### "Учебный совет"

**Условие**:
В управляющий совет школы входят родители, учителя и учащиеся школы, причём родителей должно быть не менее одной трети
от общего числа членов совета. В настоящий момент в совет входит N человек, из них K родителей.
Определите, сколько родителей нужно дополнительно ввести в совет, чтобы их число стало состовлять не менее трети от числа членов совета.

**Решение**: будем искать минимальное количество родителей, которых нужно добавить, бин поиском.
Не забываем, что новые родители добавляются к общему числу членов совета.
Не используем деление. L = 0, R = N.

Пока мы добавили мало родителей - всё плохо. Начиная с какого-то момента их стало больше трети.
Задача первого класса - "сначала плохо", "потом хорошо".

Пусть N человек всего и из них K-родителей. Мы добавили M родителей ещё. Тогда нам нужно проверить,
что при добавлении этих M-родителей, результирующее число родителей будет больше или равно трети.
```
1) K+M/N+M >= 1/3
2) Давайте уйдём от вещественного числа справа, потому что результат может получиться не точный из-за того, что мы уйдём в вещественные числа, поэтому: 
3) (K+M)/1 >= (N+M)/3
4) 3*(K+M) >= (N+M)
```
Вот что значит **не используем деление**.

Очень важно в бинарном поиске правильно определять границы L и R.
L мы взяли как 0, потому что в учебном совете может уже быть изначально N/3 родителей.
R мы взяли как N - это не расточительство, так как логарифм - это маленькая функция и растёт она медленно,
то лучше взять заведомо правильное число - это нормально.

Ещё важно следить за перполнением.
```py
def lbinsearch(l,r,check,checkparams):
	while l < r:
		m = (l+r)//2
		if check(m, checkparams):
			r = m
		else:
			l = m+1
	return l

def checkendownment(m, params):
	n, k = params
	return (k+m)*3 >= n+m

def main():
	n = 18 # всего человек
	k = 3  # из них k родителей

	l = 0
	r = n

	needle = lbinsearch(l, r, checkendownment, (n, k)) # 5
	print(needle)


if __name__ == '__main__':
	main()
```

### "Собеседование"

**Условие**:
Юра решил подготовиться к собеседованию в Яндекс.
Он выбрал на сайте leetcode N задач. В первый день Юра решил k задач, а в каждый следующий на одну задачу больше, чем в предыдущий.
Определите, сколько дней уйдёт у Юры на подготовку к собеседованию.

**Размышления**:
Можно решить задачу через формулу. Можно решить задачу через моделирование: каждый день прибавлять +1 и так далее, но это не пройдёт при больших ограничениях.
Поэтому, попробуем решить задачу бинарным поиском. Сначала всё плохо - Юра решил недостаточно задач. С какого-то дня в будущем Юра решит достаточно задач. 
Напоминает модель, когда сначала всё плохо, а затем становится всё хорошо, поэтому будем решать задачу соответствующим образом.

Будем искать минимальное количество дней, достаточное для решения не менее N задач, бинарным поиском. Нам понадобится формула арифметической прогрессии. L=0,R=N.
Для того, чтобы понять сколько задач решит Юра в M-ый день, нам понадобится формула арифметической прогрессии.

**Решение**:

- (В) Сколько будет решено задач в M-ый день ?
- (О) это будет сумма ряда - `k+(k+1)+(k+2)+...+(k+m-1)`, где k=1 - столько **новых** задач решается каждый день относительно предыдущего.
- (В) Почему в конце `-1`?
- (О) Пусть M=2, тогда в первый день он решил 1 задачу, а во второй (и последний) он решил 1+2-1 = 2. Всё сходится.

- (В) Что заметил маленький Гаус, открывший формулу арифметической прогрессии ?
- (О) Что сумма первого с последним, второго с предпоследним и так далее одинакова и равна `2k+M-1`: `k+m-1 + k = 2k+m-1`, `k+1 + k+m-2 = 2k+m-1`.
  Количество таких пар всего `M/2`, если всего `M` слагаемых, поэтому эту сумму мы умножаем на M/2: `(2k+M-1)*M/2`.
- (В) Зачем умножать на `M/2` ?
- (О) Потому что нам нужна сумма решенных задач на M-ый день. А мы знаем только формулу суммы для крайних элементов арифм. прогрессии, поэтому
      чтобы найти общее количество решённых задач в M-ый день умножить эту сумму крайних на M/2.

```py
def lbinsearch(l,r,check,checkparams):
	while l < r:
		m = (l+r)//2
		if check(m, checkparams):
			r = m
		else:
			l = m+1
	return l

def checkendownment(m, params):
	n, k = params
	return ((2*k+m-1)*m)//2 >= n

def main():
	n = 100 # всего задач
	k = 0 # уже решено задач

	l = 0
	r = n

	needle = lbinsearch(l, r, checkendownment, (n, k)) # 15 дней
	print(needle)


if __name__ == '__main__':
	main()
```

### "Лекция"

**Условие**:
Михаил читает лекции по алгоритмам. За кадром стоит доска размером `W*H` сантиметров. Михаилу нужно разместить на доске `N` квадратных
стикеров со шпаргалками, при этом длина стороны стикера в сантиметрах должна быть целым числом.
Определите максимальную длину стороны стикера, чтобы все стикеры поместились на доске (и не пришлось щуриться =)

**Размышления**:
Очень хочется разделить площадь доски на площадь квадратика и получить количество необходимых квадратиков. Но может так получитсья,
что останется ещё место - то есть стикеры займут доску не полностью. Поэтому мы можем воспользоваться бинарным поиском, чтобы
найти подходящий размер стикера на доску: то есть нам нужно найти самый большой размер стикера, который займёт доску полностью.

Это задача "второго класса". По известному размеру доски `W*H` и по известному размеру квадратика `M*M`, мы определяем сколько квадратиков
поместится и если у нас поместилось достаточное количество, то всё хорошо, а если слишком мало, то всё плохо и нам нужно найти самый большой
размер такого квадратика, чтобы всё поместилось.

**Решение**:
L = 0, R = W+H потому что мы можем взять заведомо большее значение, которое уж точно будет плохим (если площадь `W*H=1*2=2`, то `R=3`)
Возьмём такое неравенство: `(W//M) * (H//M) >= N`, чтобы сторона квадратика была кратна ширине доски и длине доски тоже и общее таких квадратиков было` >= N`.

```py
def rbinsearch(l,r,check,checkparams):
	while l<r:
		m = (l+r+1)//2
		if check(m, checkparams):
			l = m
		else:
			r = m-1
	return l

def checkparams(m, params):
	w,h,n = params
	return (w//m)*(h//m) >= n

def main():
	w = 20, h = 40 # размер доски
	n = 100 # необходимое количество шпор

	# минимальное значение стороны квадратной шпоры = 0, а максимальное = w+h.
	l = 0 
	r = w+h

	needle_length_of_side = rbinsearch(l, r, checkparams, (w,h,n))
	print(needle_length_of_side) # 


if __name__ == '__main__':
	main()
```

### "Последовательность"


**Условие**: Задана отсортированная по неубыванию последовательность чисел из N чисел и число X.
Необходимо **определить индекс первого числа в последовательности, которое больше либо равно X**.
Если такого числа нет, то вернуть число N.

Решение:
Сначала всё плохо - числа меньше, чем X, а затем становится всё хорошо, когда числа становятся >= X.

```py
def lbinsearch(l,r,check,checkparams):
	while l != r:
		m = (l+r)//2
		if check(m, checkparams):
			r = m
		else:
			l = m+1
	return l

def check(m, checkparams):
	seq, x = checkparams
	return seq[m] >= x

def main():
	seq = [1, 2, 4, 5, 10, 16]
	print("Checking sequence: ", seq)

	x = 3
	ans = lbinsearch(0, len(seq), check, (seq, x))
	if (ans >= len(seq)):
		print("cannot find this num, return N: ", len(seq))
	else:
		print("idx = ", ans, "; value = ", seq[ans])

	x = 9
	ans = lbinsearch(0, len(seq), check, (seq, x))
	if (ans >= len(seq)):
		print("cannot find this num, return N: ", len(seq))
	else:
		print("idx = ", ans, "; value = ", seq[ans])

	x = 10
	ans = lbinsearch(0, len(seq), check, (seq, x))
	if (ans >= len(seq)):
		print("cannot find this num, return N: ", len(seq))
	else:
		print("idx = ", ans, "; value = ", seq[ans])

	x = 40
	ans = lbinsearch(0, len(seq), check, (seq, x))
	if (ans >= len(seq)):
		print("cannot find this num, return N: ", len(seq))
	else:
		print("idx = ", ans, "; value = ", seq[ans])

if __name__ == '__main__':
	main()
```

### Задача об ануитентном платеже.

Условие: известна сумма кредита, срок в месяцах и ежегодный процент. Необходимо посчитать размер ежемесячного аннуитентного платежа.
Аннуитетные платежи — это выплаты по кредиту равными суммами (основной долг плюс проценты) в течение всего срока.
Такая схема позволяет заемщику планировать бюджет, так как размер ежемесячного платежа фиксирован.
Однако в начале срока большая часть платежа уходит на погашение процентов, а к концу кредита — на основной долг

Пример:
Вы взяли кредит на $1000 на 10 лет.
Ежемесячный платеж составит, к примеру, $12.
В первый месяц на проценты уйдет $10, а на основной долг — $2.
Во второй месяц, при меньшем остатке долга (осталось 8 долларов), на проценты уйдет меньше ($9), а на основной долг — больше ($3). 

```py
# проверяем, сможем ли мы выплатить кредит за periods месяцев,
# если в месяц будем платить `mpay` денег.
def checkcredit(mpay, params):
	periods, creditsum, mperc = params
	for i in range(periods):
		percpay = creditsum * (mperc / 100) # платёж по процентной части кредита в i-ый месяц
		creditsum -= mpay-percpay           # вычитаем из тела кредита число денег на проценты (percpay) и разность вычитыем из тела кредита.

	return creditsum <= 0

def fbinsearch(l, r, eps, check, checkparams):
	while (l+eps) < r:
		m = (l+r)/2
		if check(m, checkparams):
			r = m
		else:
			l = m
	return l

def main():
	eps = 0.01
	m = 10000000
	n = 300 # 25 years
	# mperc нужно рассчитать, в зависимости от годового процента, выше.
	monthlypay = fbinsearch(0, m, eps, checkcredit, (n,m,mperc))
	print(monthlypay)

if __name__ == '__main__':
	main()
```

То есть ануитентный платёж состоит из двух частей - это число по процентам и тело кредита.
Сначала в ту сумму, которую мы платим в месяц, входит больше процентной части, чем части кредита.
Но с каждой выплатой по телу кредита (строка №375), тело несколько сокращается, а это означает, что с каждым месяцем,
части, выплачиваемой по процентам, становится меньше, так как в предыдщущем месяце тело кредита сократилось,
а именно относительно этого тела и рассчитывается остаток по платёж по кредиту.

**Вывод: в каждом месяце, часть платежа по процентам сокращается за счёт уменьшения тела кредита на предыдущем месяце**.

## Тернарный поиск

Это способ искать минимум вогнутой функции или максимум выпуклой ф-ии.
Идея: мы разбиваем область поиска на 3 части и вот в этих точках на линиях разбиения вычисляем значения этой функции.
Нужно понять, возврастает или убывает функция в т-ке x ? Если возрастает, то отбрасываем правую половину, а если убывает, то отбрасываем левую.
А как это понять ? Необходимо посчитать её в точке `x` и в точке `x+e`. Если во второй точке, сдвинутой от `x` на эпсилон, ф-ия возрастает, то значит отбрасываем правую часть (от `x+e`), а
если убывает, то значит отбрасываем левую часть.
Если мы ищем оптимиум (минимум или максимум), то ответ будет там, где фунция не убывает и не возрастает или говоря по математически, то там, где производная будет равна нулю.

### Задача о велосипедистах

**Условие**: есть N велосипедистов, которые стартуют в точках x1, x2, ..., xn и движутся с постоянным скоростями v1, v2, ..., vn.
Необходимо определить момент времени, когда расстояние между лидером и замыкающим будет наименьшим.

**Решение**: для решения этой задачи можно воспользоваться троичным поиском и функцией расстояний между лидером и замыкающим велосипедистами и далее анализировать эту функцию:
если в точке M+e ф-ия расстояний между велосипедистами возрастает, то мы говорим, что мы будем обрезать справа до M+e (r = M+e), если убывает, то l=M и в итоге мы найдём точку, в которой производная =0, что
означает, что велосипедисты находятся на минимальном расстоянии. 

```py
def dist(t, params):
	x, v = params
	minpos = maxpos = x[0] + v[0]*t # на какой позиции первый велосипедист
	for i in range(1, len(x)):
		nowpos = x[i] + v[i]*t # на какой позиции i-ый велосипедист
		minpos = min(minpos, nowpos) # пытаемся понять, а является ли этот велосипедист замыкающим, посредством значения координаты в момент времени t 
		maxpos = max(maxpos, nowpow) # пытаемся понять, а является ли этот велосипедист лидером, посредством значения координаты в момент времени t

	# возвращаем разницу в расстояниях между лидером и замыкающим велосипедистами в момент времени t.
	return maxpos - minpos 

def check(t, eps, params):
	return dist(t+eps, params) >= dist(t, params)

def fbinsearch(l, r, eps, check, checkparams):
	while (l+eps) < r:
		m = (l+r)/2
		if check(m, eps, checkparams):
			r = m
		else:
			l = m
	return l

def main():
	l = 0  # все начали движение "по свистку"
	r = 30 # и гонка продолжалась 30 минут

	x = [1, 2, 3, 4, 0, 10, 12]   # значения стартовых координат каждого велосипедиста из len(x)
	v = [10, 9, 8, 11, 12, 6, 5]  # значения скоростей, с которыми эти велосипедисты движутся 

	moment = fbinsearch(l, r, 0.0001, check, (x, v))
	print(moment)
```
